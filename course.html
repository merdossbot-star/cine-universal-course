01 · Architecture

Les responsabilités ne se mélangent pas.

DSS porte les données, CSS la présentation, ASS le comportement, BSS la composition et LSS le graphe de l’application.

02 · Les cinq langages

Chaque extension a une raison d’exister.

DSS · données

Constantes, tableaux, objets, couleurs, dimensions, endpoints, flags d’environnement et imports. Les `@const` et `@data` sont exportés selon les règles du langage.

CSS · design

Styles, variables et canaux. L’expansion compile-time peut fournir des valeurs, tandis que var(--cine-…) reste un canal runtime.

ASS · comportement

Événements, actions, états, attributs, propriétés, texte, HTML de confiance et lifecycle.

BSS · composition

Templates, éléments, slots et conditions. Le for dynamique reste un mécanisme runtime ; @each est compile-time.

LSS · application

Pages, layouts, composants, plugins, routes, resources, environnement et références vers DSS/CSS/ASS/BSS/JS.

HTML · socle

Le HTML reste le support sémantique ; CINE l’améliore par comportement, données, composition et cinématique.

03 · Hello World

Aucun fichier CINE ne doit être vide.

Le laboratoire fournit un vrai mini-projet avec du code dans chaque extension. Les fichiers sont visibles ci-dessous et la sortie compilée est testable dans le navigateur.

hello.dss

@const title = "Hello CINE";
@const accent = #0af;
@data user { name: "World"; };

hello.css

@use "hello.dss";
.hero { color: #{dss.accent}; padding: 24px; }

hello.ass

@use "hello.dss";
#hello {
  on click -> action("hello.click");
  text <- dss.title;
}

hello.bss

template "hello" () {
  section.hero {
    text <- dss.title;
  }
}

hello.lss

@use "hello.dss";
app "hello" {
  html "./index.html";
  css ["./hello.css"];
  ass ["./hello.ass"];
  bss ["./hello.bss"];
}

index.html

<main id="hello">
  <div data-cine-root></div>
</main>

04 · Compiler & validation

Un fichier ne doit pas seulement être parsé.

La chaîne de preuve devient : structure → langage → sémantique → liaison → préparation runtime → preuve cible.

Structure
Automate à pile pour délimiteurs, chaînes et commentaires.
Syntaxe
Parser spécifique au langage.
Sémantique
Variables, scopes, types, capabilities et effets.
Liaison
Imports, packages, routes, plugins et ressources.
Preuve
Build, trace comportementale et tests de target.
cine check project/
cine compile main.lss
cine build main.lss --out dist/
cine slice main.lss --out dist/slice/
cine target main.lss --target android.views
05 · Universal Instances

Chaque événement ou tâche devient une instance CINE.

La contrainte d’instance donne une unité commune pour l’événement, l’animation, la cinématique, les tâches, les modèles IA et l’observation.

const instance = Cine.universal.create({
  id: "button.submit.click",
  kind: "event",
  actor: "submitButton",
  inputs: { source: "pointer" },
  vars: { progress: 0, velocity: 0 },
  actions: ["validate", "save", "navigate"],
});
Cine.universal.instances.set(instance.id, instance);
Le stockage recommandé pour le runtime est une Map indexée par ID. Elle permet l’accès O(1), la sérialisation contrôlée et la génération d’un catalogue d’instances pour l’observabilité et l’IA.

07 · Framework X

Analyser, classifier, traduire ou attendre.

Le parser d’interop suit les imports, symboles, scopes, types et constructions. Une API inconnue n’est jamais inventée : elle devient BRIDGED, RESIDUAL ou UNSUPPORTED.

Framework X
  → Language AST/CST
  → Semantic Model
  → Capability Graph
  → CINE IR
  → CINE alternative
  → compile/check
  → differential proof
08 · JSDK local

Le SDK comme magasin local de packages analysés.

Une liste de liens peut alimenter l’ingestion. Les imports internes du package sont suivis récursivement ; les secrets sont détectés et les artefacts d’analyse sont nettoyés ; un package non certifié reste en attente plutôt qu’être présenté comme « implémenté ».

cine sdk add https://registry.npmjs.org/…
cine sdk scan ./packages/my-lib
cine sdk graph my-lib
cine sdk inspect my-lib
cine sdk certify my-lib

10 · Avancé

3D, maps, vidéo, SVG, Canvas et cinématique.

Ces capacités doivent rejoindre le même modèle : une capability, une instance, un graph de dépendances, un adapter de plateforme et une preuve.

3D

Three.js, Babylon.js, PixiJS, WebGPU/WebGL → CINE render graph.

Maps

Leaflet, MapLibre, OpenLayers, Mapbox → CINE geo graph + layers.

Video

Video.js, HLS.js, Shaka Player → media resource + timeline.

Drawing

SVG, Canvas, Fabric, Konva, D3 → vector/canvas render graph.
